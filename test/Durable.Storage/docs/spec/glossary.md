# Glossary

Every term the specification uses, in alphabetical order, with the file which owns it. Identifiers in
`code` are the names the code uses for the term.

| Term | Definition | Owner |
| --- | --- | --- |
| Absence answer | A read which reports that a journal does not exist, answered from the caught-up key indexes and the archive store's `Absent` answer to `ArchiveReader.ReadStoreAsync`: on the LSM without an object-store request once the range's section metadata is preloaded, on archive logs with one read of the key's log (JS-I9). | [journals](components/journals.md#82-reads-on-the-owner) |
| `Accepted` | The write outcome "durable, and applied by the owner", carrying the journal's version after the entry. | [journals](components/journals.md#22-writes) |
| Acknowledged prefix | The prefix of slots the shared front knows is decided, its writer's completed prefix while the ledger is open or the recorded `T` once observed, which every ledger storage operation carries: the quorum's known contiguous tail, and an object-store ledger's recovery evidence. | [ledger-protocol](components/ledger-protocol.md#27-ledger-storage) |
| Admission | The primary's check, before proposing, that an entry applies to the fold of its key's history and the primary's in-flight entries of the key; an entry which applies to none of the states the in-flight entries' prefixes leave is answered `Rejected` and never proposed, and one which applies to some of them waits for their outcomes. | [journals](components/journals.md#81-admission) |
| `AdmissionGate` | `Orleans.Durable.Storage.Engine.Threading`'s ordering of each operation's admission against its owner's close. | [conventions](conventions.md#11-admission-and-close) |
| `Ambiguous` | The outcome which asserts nothing: a proposal whose ledger left the map before its primary learned the recovered tail, or a write whose reply was lost, which may still be decided, at most once. | [outcomes](outcomes.md#4-ledgers) |
| `Append` | The row kind which applies on top of its key's earlier rows, and the journal entry kind which writes one, adding a non-empty payload. | [journals](components/journals.md#21-journal-semantics), [ledgers](components/ledgers.md#22-rows-batches-and-tags) |
| Append run | A key's write for a segment which holds no `Replace` or `Delete` of the key: its `Append`s in order, which archive logs append to the current generation. | [archive](components/archive.md#21-history-of-a-key) |
| `AppendOutcome` | A `LedgerWriter` append's answer: `Appended(Slot)`, durable at its slot; `Sealed(Slot)`, a write which met a seal; or `Unresolved(Slot?)`, an acquisition or completion which could not complete. Ledgers decides the last two from the ledger map. | [ledger-protocol](components/ledger-protocol.md#24-append-outcomes) |
| `Applied` | The commit outcome "the change's goal holds in a value written or read after its submission"; it carries that value's epoch. | [ledgers](components/ledgers.md#26-transitions) |
| Applied position | The slot below which a node has applied a ledger's decided batches to its key index and, on the primary, to its warm state. | [journals](components/journals.md#83-warm-state) |
| Apply loop | A node's application of each replicated ledger's decided batches, in slot order, which `LedgerApplyLoop` delivers to the node's `LedgerApplier` as resolved rows ([ledgers §8.5](components/ledgers.md#85-replica-lifecycle-on-a-node)); on the primary it completes their entries `Accepted`. | [journals](components/journals.md#81-admission) |
| `ArcBuffer` | A reference-counted, zero-copy owned view of a byte range across pooled pages; the type in which owned payloads cross layers. | [buffers](components/buffers.md#2-contract-upward) |
| Archive | The layer which keeps every key's history, `History(k)`, across the live ledgers and the archive store, reads it, and holds the archive store contract (`IArchiveStore`); its two implementations are the LSM and archive logs. | [archive](components/archive.md) |
| Archive prefix | `ArchivePrefix`: an archive store's answer for a key, the commands it holds: its `Token`, `VersionBase`, whether a `Replace` opened its base (`HasBase`), its `Tombstone` while the key is deleted, its content, and its coverage, which `Holds` reads to mark the rows the prefix holds; a reader scans each listed ledger from slot 0 on every store. | [archive](components/archive.md#4-data-types) |
| Archive store | The store the live ledgers drain into, one per cluster for its life: the LSM or archive logs, each implementing `IArchiveStore`. | [archive](components/archive.md#3-requirements-downward) |
| Archive log | The log of one key in archive logs: a sequence of generations, the highest current, each the content its opener wrote once followed by the appends of the append runs which extended it; its content is the replay of every command of the key it holds. On Azure, Orleans Journaling's own layout, `wal/{id}` and `checkpoints/{id}/{g:D20}`. | [archive logs](components/archive-logs.md#21-archive-logs) |
| Archive logs | The archive store which keeps one archive log per key, written once per key per closed segment of each ledger, in segment and lineage order, with the live ledgers as its write-ahead log. | [archive logs](components/archive-logs.md) |
| Archive token | A key's opaque token for one segment, at most 32 bytes, minted by the archive provider and stored once, in the key's defining row: `Origin` for its first segment, `Plan` of its previous token and write, or a prefix's `Token` after a rebase (JS-I10). Only the provider decodes it; the LSM's is empty. | [archive](components/archive.md#21-history-of-a-key) |
| Archive-log store | The archive-log storage contract (`IArchiveLogStore`), stateless: reads, properties reads, and appends and openers each conditional on the log's position; memory, Azure append blobs, or chunk objects. | [archive logs](components/archive-logs.md#3-requirements-downward) |
| Backpressure (answer) | A ledger replica's answer to an operation it rejected before retaining or writing anything, so it has no effect; a `Ledger`'s, when a replica answered it and the operation could not decide, asserts nothing, and its writer repeats it. | [outcomes §1](outcomes.md#1-ledger-replicas) |
| Base (key) | A key's last `Replace` or `Delete` row, which supersedes every earlier row. | [ledgers](components/ledgers.md#22-rows-batches-and-tags) |
| Batch | The rows of one slot's DATA value in proposal order, each with its key in the ledger's range: at least one, except a marker; it carries its segment's start flag, offset, and ordinal base. | [ledgers](components/ledgers.md#22-rows-batches-and-tags) |
| Block cache | A host's cache of the LSM blocks on its volatile disk, keyed by `(object, block)`: region files with FIFO eviction and S3-FIFO admission, and a CRC-32C per block. | [archive LSM](components/archive-lsm.md#87-caches) |
| Bloom filter | A section's filter over its keys, which lets a read skip a section that cannot hold a key. | [archive LSM](components/archive-lsm.md#7-formats) |
| BookKeeper's terms | Clog's names for Apache BookKeeper's: a bookie's journal is the WAL, a ledger entry is a batch at a slot, fencing is the seal, LAC + 1 is the contiguous tail, an ensemble is a replica set, and a ledger handle is a `Ledger`. | [ledger-protocol](components/ledger-protocol.md#1-purpose-and-scope) |
| `CallBudget` | `Orleans.Durable.Storage.Engine.Threading`'s FIFO budget of bytes and calls: it grants each call in arrival order, so none overtakes another, and fails a waiting call with its owner's timeout only at the call's deadline, one absolute time from the call; a replica transport's per-node lanes. A budget of calls alone (`ForCalls`) is a FIFO slot gate whose calls may wait with no deadline: the Journals' history-read slots and the owner's forwarded-read slots. | [ledger-replicas](components/ledger-replicas.md#22-iledgerreplicatransport) |
| Candidate end | The position at which one recovery ended a ledger (`RecoverAsync`); concurrent recoveries may return different ones, and only the map's conditional write makes one the recovered tail. No replica retains it. | [ledger-protocol](components/ledger-protocol.md#22-recovery) |
| Catalog | The LedgerStore's record of the ledger replicas a node holds, their handles and first files, the tombstones of the ledgers it dropped, and the next handle: the newest `CLSC` catalog checkpoint with the later create and drop records in the node's WAL applied. | [ledgerstore](components/ledgerstore.md#5-invariants) |
| Checkpoint (slot-index) | An incremental `CLSI` persistence of one ledger replica's slot table, reflecting exactly the WAL records below its replay start. | [ledgerstore](components/ledgerstore.md#8-mechanism-and-policy) |
| Classic-recovery quorum | The Fast CASPaxos quorum (3 of 5) which preserves a chosen value when the fast path cannot form. | [metastore](components/metastore.md#8-mechanism-and-policy) |
| Closed | A ledger's status once a recovery found its recovered tail `T` and the map records `Closed(T)`; its rows are final. | [ledgers](components/ledgers.md#4-data-types) |
| Cluster | The non-empty GUID of one deployment: every storage root records it once and refuses another, and every MetaStore register key carries it. | [identity](identity.md#1-cluster) |
| Cluster claim | The file `{root}/cluster` of a node root, holding the cluster identifier which owns the root; created once and never overwritten. Archive stores keep no claim: each lies under its cluster's store prefix. | [identity](identity.md#1-cluster) |
| Commit rule | The condition a change must meet against the value it is applied to: for a ledger-map change, every ledger it closes open, every open ledger overlapping a range it opens closed by it, and the ledger it drops closed with no listed lower-ID ledger overlapping it; for a drain, its starting watermark; for a compaction, its inputs listed. | [ledgers](components/ledgers.md#26-transitions) |
| Committer | The control-plane class through which every write of the ledger map (`LedgerMapCommitter`), the manifest (`ManifestCommitter`), or the node registry (`NodeRegistryCommitter`) passes, one per register: it applies each change only under its commit rule, by conditional write; a write whose outcome is unknown ends its batch with one read, which answers the changes it decides, and the rest fail as while the store is unavailable ([conventions §6](conventions.md#6-retries-and-idempotency)). | [ledgers](components/ledgers.md#26-transitions) |
| Compaction | An LSM worker's merge of committed sections into new sections under the drop rule, committed by replacing its inputs iff every input is still listed (LSM-I5). | [archive LSM](components/archive-lsm.md#82-compaction) |
| Compaction output | A run object `c/{partition}/{id}` which a compaction writes; its trailer lists its inputs. | [archive LSM](components/archive-lsm.md#7-formats) |
| Complete | A closed ledger whose watermark reached its recovered tail: the LSM holds all of its rows, and it may leave the ledger map (LSM-I3). `ManifestValue.IsComplete(S)`: `S < DrainedBelow`, or `S` is marked complete. | [archive LSM](components/archive-lsm.md#5-invariants) |
| Composition | An assembly of the layers for a deployment: Orleans journaling. | [README](README.md#23-compositions) |
| Composition requirement (R1–R6) | A property a layer requires of the composition which hosts it, stated in the layer's "Requirements downward". | [system-model](system-model.md#6-composition-requirements) |
| Contiguous tail | A ledger's decided prefix: while the ledger is open, one above the last slot its writer completed, all of them completing in order; once it is closed, the recorded `T`. Every lower slot holds a batch on `Q` replicas. A known contiguous tail is any value at most it. | [ledger-protocol](components/ledger-protocol.md#1-purpose-and-scope) |
| Control plane | The state and processes which decide who stores and serves what, and change it: the ledger map, the manifest, the node registry, the committers, the controllers, transition executors, node reconciliation, and drain, compaction, and sweep workers. Its interfaces are in each layer's `.Control` namespace; it is off the request path. | [README](README.md#21-control-plane-and-data-plane) |
| Controller | A process of the composition which applies policy and chooses transitions: placement and balancing, failure detection and takeover, split and merge, rolls, drain and compaction scheduling, drops, and sweeping. Duplicates are safe. | [README](README.md#21-control-plane-and-data-plane) |
| Controller grain | `IClusterControllerGrain`, where the Orleans composition's control plane decides: it hosts the group committers of the ledger map, the manifest, and the node registry, chooses transitions, and runs the policies. The request path never calls it. | [orleans](compositions/orleans.md#56-controllers) |
| Corruption | Stored bytes which fail their integrity check or contradict an invariant; always reported as corruption, never as missing. | [outcomes](outcomes.md#8-error-taxonomy) |
| `CorruptionEnd` | The WAL page below which a LedgerStore replica's state is uncertain after replay met damage. | [ledgerstore](components/ledgerstore.md#4-data-types) |
| CRC-32C | The Castagnoli CRC used for every integrity check in Clog. | [conventions](conventions.md#4-integrity) |
| Coverage | `N − Q + 1` of a ledger's replicas: enough that no `Q` replicas lack a property they share (Vanlightly's quorum coverage). Seals and recovery's absence need it. | [ledger-protocol](components/ledger-protocol.md#5-invariants) |
| DATA entry | A register's non-empty value written by an append. | [ledger-replicas](components/ledger-replicas.md#1-purpose-and-scope) |
| Data plane | The processes and objects which move entries: primaries, replicas, readers, LSM objects, and caches, including each process's views of the ledger map and the manifest. Its types are in each layer's root namespace and reference no control-plane type. Every host runs it beside the application. | [README](README.md#21-control-plane-and-data-plane) |
| Decided | Of a ledger's slot: holding DATA on `Q` replicas, below a known contiguous tail or the map's recorded `T`. A closed ledger's decided rows are exactly its DATA below `T` (LG-I4). | [ledgers](components/ledgers.md#24-primary-ledgerwriter) |
| Decided end | Of a live ledger: the map's `T` once it is closed, and, while it is open, a contiguous tail its reader learned or the tail its primary's open check confirmed. Every slot below it is decided. | [ledgers](components/ledgers.md#25-reads-ledgerreader) |
| Defining row | A key's first row in a segment: it carries the full key, the key's version before it, and its archive token for the segment, and takes the segment's next ordinal. | [ledgers](components/ledgers.md#22-rows-batches-and-tags) |
| `Delete` | The row kind which supersedes every earlier row of its key and leaves its body, when it has one, as the key's tombstone; and the journal entry kind which ends a journal's content, its row's body the 8-byte tombstone, the writer's deletion time. | [journals](components/journals.md#21-journal-semantics), [ledgers](components/ledgers.md#22-rows-batches-and-tags) |
| Diskless ledger | An object-store ledger: its node's disk holds only derived caches. | [object-store ledgers](components/object-ledgers.md) |
| Drain | A worker's flush of a ledger's closed segments into the archive store, whole and in order: on the LSM, one segment into one new object with one section, committed iff the watermark is the segment's start (LSM-I1, LSM-I2); on archive logs, one conditional write per key per segment, then the segment's marker, once no older overlapping ledger is listed (LOG-I3). | [archive LSM](components/archive-lsm.md#81-drain), [archive logs](components/archive-logs.md#81-drain) |
| Drain marker | The object `durable-storage/d/{S:D20}/{start:D20}`, created once when a segment's drain into archive logs completes; its content is the segment's end slot, from which a restarted drain resumes. | [archive logs](components/archive-logs.md#75-clogs-objects) |
| Drain output | A run object `d/{S}/{a}/{id}` holding exactly ledger `S`'s decided rows over the drained slots (LSM-I2). | [archive LSM](components/archive-lsm.md#7-formats) |
| `DrainedBelow` | The manifest's ledger ID below which every ledger is complete; it never decreases. | [archive LSM](components/archive-lsm.md#22-manifest-view) |
| Drop (ledger) | A map change, `LedgerMapChange.Drop(S)`, not a transition, which removes a closed, complete ledger from the ledger map once no listed ledger with a lower ID overlaps it (LG-I10); each replica node then drops its replica at its next reconciliation. | [ledgers](components/ledgers.md#26-transitions) |
| Drop (replica) | A node's removal of a ledger replica, with its seal, at the layer above's direction (`ILedgerStore.DropReplicaAsync`), which records its tombstone, leaving the ledger sealed and dropped: afterwards every operation answers `Dropped`, and the replica is never created again (LR-I3). | [ledger-replicas](components/ledger-replicas.md#5-invariants) |
| Drop rule | Compaction's rule for omitting rows: a row which a newer `Replace` or `Delete` of its key among the inputs supersedes, and an empty `Delete` only when no older row of its key lies outside the compaction (LSM-I5). | [archive LSM](components/archive-lsm.md#82-compaction) |
| `Durable` | The proposal outcome "the batch is the decided DATA at its slot, and every lower slot is decided". | [ledgers](components/ledgers.md#24-primary-ledgerwriter) |
| Durable linearizability | Linearizability over durable state: an operation's effect is durable before its answer, and a read returns only durable values, so the history after any crash extends every answer given before it. | [metastore](components/metastore.md#3-requirements-downward) |
| Durable watermark | A ledger's watermark as of the journal index's last completed atomic flush; replay resumes there after a crash. | [journals §8.3](components/journals.md#83-warm-state) |
| Dyadic range | A node of the binary trie over a key's bits, `(prefix, depth)`: the keys whose first `depth` bits equal `prefix`. Two dyadic ranges nest or are disjoint. Ledger ranges and LSM partitions are dyadic. | [ledgers](components/ledgers.md#21-keys-and-ranges) |
| Entry | One journal change, carried by one row: `Append`, `Replace`, `Delete`, or `Expired`. | [journals](components/journals.md#21-journal-semantics) |
| Entry kind | `Append` (an `Append` row), `Replace` (a `Replace` row), `Delete` (a `Delete` row with the 8-byte tombstone), or `Expired` (an empty `Delete` row). | [journals](components/journals.md#42-entries-and-rows) |
| Entry record | Journals' encoding of one entry, carried verbatim from the writing process to the key's primary and never stored: a CRC-32C over the row key and the record, the kind, the expected version, a `Delete`'s deletion time, and the body. | [journals](components/journals.md#7-formats) |
| Epoch (ledger map) | A counter in the ledger map which every map write increments; map views keep the newest value by it. | [ledgers](components/ledgers.md#23-ledger-map) |
| Epoch (manifest) | A counter in the manifest which every commit increments; views and commit outcomes compare it. | [archive LSM](components/archive-lsm.md#22-manifest-view) |
| Executor | `TransitionExecutor`, in the process of the node a transition names: it recovers the ledgers the transition closes (`RecoverAsync`), creates the `LedgerWriter`s, and their sequencer lifetimes, of those it opens, and submits the map change once through an in-process `commit` delegate its caller creates; once the map lists them, its process is their primary. | [ledgers](components/ledgers.md#26-transitions) |
| `Expired` | The journal entry kind which empties a deleted journal once its tombstone's retention has passed; only the primary writes it. An empty `Delete` row. | [journals](components/journals.md#21-journal-semantics) |
| Extent | An append-layout object-store ledger's object: an Azure append blob holding the frames of consecutive slots from the slot its name encodes, ending at most once with a `ROLL` to the next extent. | [object-store ledgers](components/object-ledgers.md#7-formats) |
| Fast quorum | The Fast CASPaxos quorum (4 of 5) which lets a write complete in one round trip. | [metastore](components/metastore.md#8-mechanism-and-policy) |
| `Fenced` | The proposal and journal write outcome "not in the ledger, and never will be": the ledger was sealed, and its recovered tail lies at or below the batch. No effect. | [outcomes](outcomes.md#4-ledgers) |
| File (WAL) | One numbered log file `{file:D20}.clfl` of a WAL directory; each open appends to files it creates. | [wal](components/wal.md#7-formats) |
| Fold | The application of a key's rows in tag order under their row kinds; a journal's state is the fold of its history. | [ledgers](components/ledgers.md#22-rows-batches-and-tags) |
| Generation | One stretch of an archive log, from the opener which created it: its checkpoint holds the opener's base, a `Replace`'s body or nothing for a `Delete`, then the segment's later appends, and later append runs extend it. A generation has a base only when a `Replace` opened it; a key's first append run creates generation 1, with no base. A `Delete` opens a generation too, so logs are never deleted. | [archive logs](components/archive-logs.md#21-archive-logs) |
| Grid depth | A depth of the LSM's partitions, a multiple of `b` key bits (4 by default); a drain writes at the deepest grid depth containing its ledger's range, and a push moves sections one grid step deeper. | [archive LSM](components/archive-lsm.md#88-policy) |
| Group committer | `LedgerMapCommitter`, `ManifestCommitter`, or `NodeRegistryCommitter`, a committer which batches concurrent submissions into one conditional write, folding the batch in submission order so each change whose goal is absent and whose commit rule holds against the result of those before it applies, and answering each from a value written or read after its submission; one write is in flight at a time. All three are `GroupCommitter` (`Orleans.Durable.Storage.Engine.GroupCommit`) under their value's commit rules ([conventions §6](conventions.md#6-retries-and-idempotency)). | [ledgers](components/ledgers.md#26-transitions) |
| Handoff | A planned `Replace`, executed in the target's process as a takeover is: its recovery seals the ledger, and the old primary, once its next append meets the seal, helps by recovering from its own contiguous tail. | [ledgers](components/ledgers.md#26-transitions) |
| Held | Of a decided row: covered by a store's prefix, `Holds(prefix, write, i)` for the key's write in the row's segment, applied or superseded. A history read scans every live row from slot 0 and returns a held row with its length only. | [archive](components/archive.md#21-history-of-a-key) |
| Hold (a claim) | A process holds a primary claim while the `LedgerWriter` whose sequencer lifetime the claim names runs in it; a lifetime stops when its ledger closes or leaves the map, when the change which created it can no longer apply, or when its writer meets a seal or cannot complete an append. | [ledgers](components/ledgers.md#24-primary-ledgerwriter) |
| History | `History(k)`: key `k`'s archive prefix followed, in tag order, by its decided rows in the live ledgers which the prefix does not hold, each command counted once. | [archive](components/archive.md#21-history-of-a-key) |
| Hole page | A WAL page which recovery wrote over a page a crash left incomplete; scans report it as `WalTorn`. | [wal](components/wal.md#7-formats) |
| Host | A process which runs the data plane beside the application, with one node root and a volatile disk. A host serves one cluster. | [system-model](system-model.md#1-processes-nodes-silos-and-disks) |
| In-flight entries | The entries a primary has admitted for a key whose batches are not yet decided; admission admits an entry after them, and rejects one only when it applies to no state a prefix of them leaves. | [journals](components/journals.md#81-admission) |
| Journal | An independent keyed sequence of entries, versioned by an opaque version, whose state is one pure fold of them. | [journals](components/journals.md) |
| `JournalKey` | A journal's identity: a non-empty string compared ordinally, encoded as 1 to 65,531 bytes of strict UTF-8. | [identity](identity.md#7-journal-identities-and-routing) |
| Journals | The journal layer: journals over rows, admission on the primary, versions and rebases, write outcomes, reads, tombstone expiry, and warm state. | [journals](components/journals.md) |
| `JournalState` | A journal's fold: `CurrentVersion`, existence, the deletion time, the content's length, and the key's segment, token, and `Plan` fold; absent when the key has no history. | [journals](components/journals.md#42-entries-and-rows) |
| Key | An opaque byte string of 1 to 65,535 bytes, ordered lexicographically; the unit of ownership and of history. | [ledgers](components/ledgers.md#21-keys-and-ranges) |
| Key index | A node's index, per live ledger, of the keys each decided batch touches and their tags, applied in slot order; counted only once caught up to the ledger's decided end (JS-I9). | [journals](components/journals.md#83-warm-state) |
