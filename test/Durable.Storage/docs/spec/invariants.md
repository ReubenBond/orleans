# Invariants

The traceability table: every invariant in the component and composition files, with the section which states
it, the code which enforces it, and the evidence which establishes it. The owning section is authoritative; the
statement here is a one-line summary.

- **ID prefixes** name the owning layer: BUF Buffers, WAL the WAL, LR ledger replicas, LS the LedgerStore, LP the ledger
  protocol, LL its ledger storage seam, OL object-store ledgers, MS the MetaStore, LG Ledgers, HI the Archive (it guards
  `History(k)`), LSM the Archive's LSM, LOG archive logs, SD the state database, JS Journals, and OR the Orleans
  composition.
- **Enforcing code** names `Type.Member`; the project is the component's implementation project unless given in
  parentheses. Code cites the invariant's ID next to the enforcement
  ([conventions](conventions.md#9-citations-in-code)).
- **Evidence** names test classes (with their project when it is not the component's default test project), model
  properties and mutants (Quint in `specs/ledger-protocol`, `specs/ledgers`, `specs/archive`, and `specs/archive-logs`,
  run by `eng/model-check-quint.ps1`), golden vectors under `tests/shared-vectors/`, and fuzz targets whose corpora
  under `fuzz/corpus/` the owning layer's `CorpusReplayTests` replay. Every Quint invariant has an independent mutant
  which must produce its counterexample, and the ledger protocol model adds a regression and reachability witnesses.
  The owning file's Verification section names the individual test cases.
- *Not yet in code* marks an invariant, or the named part of one, whose enforcement is not implemented.
- *Planned* marks evidence which the owning Verification section specifies and which arrives with the
  implementation. §14 lists the invariants whose evidence is planned only or partial.
