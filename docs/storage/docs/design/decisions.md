# Decision log

This log records the active architectural decisions, deliberate post-v1 deferrals, and remaining open questions for Roux. Decided items link to the design document that carries them.

## Decided

### Architecture and workspace

| Area | Decision | Where |
| --- | --- | --- |
| Language and runtime | Rust; thread-per-core Tokio (`current_thread` + `LocalSet` per core) for networking, membership, and grain execution; Tokio storage workers + Linux `io-uring` (portable `std::fs` elsewhere) narrowly scoped inside `clog-wal`. | [Overview](overview.md#scheduling), [Architecture](architecture.md) |
| Workspace monorepo (`ST1`) | All `clog-*` crates, `roux-*` crates, `roux-macros`, `xtask`, and formal models live in one Cargo workspace (14 crates: 6 `clog-*`, 6 `roux-*`, `roux-macros`, `xtask`) with an acyclic DAG where `clog-*` never depends on `roux-*`. | [Architecture](architecture.md), [Storage](storage.md#1-monorepo-workspace-and-crate-dag-st1) |
| Layered architecture | Five layers: L0 Substrates (`clog-metastore`, `clog-caspaxos`, `clog-wal`, `clog-ledgers`, `clog-archive`, `clog-journals`, `roux-id`), L1 Messaging (`roux-net`), L2 Storage (`roux-storage`), L3 Membership (`roux-membership`), and L4 Runtime (`roux-runtime`, `roux-macros`, `roux-jobs`). | [Layers](layers.md), [Architecture](architecture.md) |
| Roux built on Clog | Roux builds on the Rust implementation of Clog (`clog-*` crates) composed through `roux-storage`. Clog supplies local WAL (`clog-wal`), replicated `LedgerQuorum` (`N=3/Q=2`), `MetaStore`, dynamic dyadic `KeyRange` ledgers, SlateDB `ArchiveStore`, and `clog-journals` with an embedded WAL-less `lsm-tree` warm index. | [Architecture](architecture.md), [Storage](storage.md) |
| Time and safety | Safety never depends on synchronized clocks. Durable safety holds unconditionally via ledger seals, MetaStore CAS, and `JournalVersion`; L2 ledger-replica leases (`ST8`) bound dual activations for non-durable side effects using monotonic clocks with a bounded drift rate `ρ`. | [Overview](overview.md#time), [Storage](storage.md#7-l4-runtime-boundary-r33-r34-r36) |
| Storage outages | Object-storage or MetaStore outages stall progress while preserving safety. Local storage failures (WAL I/O error, checksum mismatch, index corruption) fail-stop the process immediately. | [Overview](overview.md#object-storage-outages), [Storage](storage.md) |
| Targets | Up to ~1,000 nodes; millions of activations per 10 nodes; 1M non-durable RPS per node; at least Orleans' efficiency. | [Overview](overview.md#targets) |
| Format upgrades (`S4`) | N−1 / N+1 rolling upgrades across wire and durable formats: nodes read the previous and next versions and write only the compatible version, gated by `ClusterConfig.format_version` in L3, handshake `protocol_version`, and standard protobuf field evolution. | [Wire catalog](wire-catalog.md), [Membership](membership.md) |
| Enroute-inspired invariants | Type-enforced durability barriers (`synced(durable_pos)` before emitting persistence-dependent acks), zero-`mmap` storage files, non-blocking actor threads (resumable async hydration for cold reads), coalesced latest-snapshot watch propagation (`LedgerMapView`, `ViewUpdate`), and strict workspace lints via `cargo xtask lint`. | [Storage](storage.md), [Testing](testing.md) |

### L0 / L1 — Identities, serialization, and messaging

| Area | Decision | Where |
| --- | --- | --- |
| Identities (`N24`, `M37`) | `ClusterId`, `InstanceId`, and `NodeId` (Clog UUID persisted in `wal/node`) are 128-bit; `ProcessId` (join `MembershipVersion`), `MembershipVersion`, and `ThreadId` are integers (`MemberId = (NodeId, ProcessId)`, 24 bytes). `GrainId { grain_type, key: Bytes }` carries a canonical protobuf-encoded key (`#[derive(roux::GrainKey)]`, string keys built in). `roux-id` is a leaf crate shared by all layers. | [Identities](identities.md) |
| Serialization (`Z1`, `Z7`, `Z15`, `Z22`) | Standard Protocol Buffers binary encoding via `prost` + pure-Rust `protox` + `prost-build` (no `protoc`, no custom codec crate). Internal wire/durable schemas are `.proto` files converted to strict Rust domain types via `TryFrom`; application types use `#[derive(prost::Message)]`. Unknown fields are dropped by default; `decode_canonical` (`roux-id`) and `reject_unknown_wire_tags` (`roux-membership`) enforce strictness where required. Closed polymorphism uses `oneof` enums; `prost_types::Any` is not used. | [Serialization](serialization.md) |
| Buffers (`N14`, `ST6`) | Standard `bytes::Bytes` / `BytesMut` everywhere in L1–L4; `AlignedBuf` (4 KiB direct-I/O alignment) lives inside `clog-wal`. No custom `ArcBuffer` or standalone `clog-buffers` crate (`io_uring` provided-buffer rings and pooled `Bytes::from_owner` pages are deferred past v1). | [Messaging](messaging.md), [Storage](storage.md) |
| Connectivity and framing (`N1`, `N2`, `N6`, `N18`) | One `roux-net` crate (internal `wire`, `transport`, `net` modules). Membership-free, mTLS-authenticated RPC over TCP (`tokio::net` + `tokio-rustls`) and in-memory streams for tests, owned by per-core `current_thread` Tokio threads. One connection per destination thread per peer; dialer sends requests and acceptor returns responses on the same connection. Varint-length-delimited `roux.wire.v1.Frame` (`Request \| OneWay \| Response`) sum types with `Payload` last and a 32 MiB payload cap (`N16`). Request IDs are per-connection varint counters. | [Connectivity](connectivity.md), [Messaging](messaging.md), [Wire catalog](wire-catalog.md) |
| Addressing and targets (`N23`) | Targets are `Service { interface, method }` or `Object { key, hint, interface, method }`. IDs `< 1024` are reserved for system targets: L1 `1–15`, L3 `16–31` (`Membership` 16, `Join` 17; `Gateway` 18 reserved), L4 `64–95` (`CallControl` 64 reserved), L2 Storage `96–127` (`MetaStoreCasPaxos` 96, `LedgerReplica` 97, `JournalForward` 98, `ClusterControl` 99, `NodeControl` 100). `NotHere` carries optional `Location { member, hint }` and opaque `version: u64` (`LedgerMap` version). | [Identities](identities.md), [Wire catalog](wire-catalog.md) |
| Priority and context (`N3`, `N11`, `S1`) | Each outbound connection has High and Normal send queues: High (membership probes, alerts, consensus) drains first and is exempt from the 32 MiB bound; Clog targets `96–100` use Normal under Clog's caller-side `CallBudget` (`ST5`), with a dedicated replica control lane for `ReadTail` seals and `Heartbeat` lease renewals. `CallContext` carries `TraceContext` and `optional string principal`. Node authentication uses cluster CA mTLS plus `tls_key_sha256` pinning verified against `Join`. | [Messaging](messaging.md), [Wire catalog](wire-catalog.md) |
| Interface schemas (`N23`, `Z12`) | Explicit unique integer IDs on grain types, interfaces, and methods; `cargo xtask schema` generates committed `contracts.proto` checked in CI for reuse or breaking changes. | [Messaging](messaging.md), [Serialization](serialization.md) |

### L2 — Storage (Clog + `roux-storage`)

| Area | Decision | Where |
| --- | --- | --- |
| `MetaStore` (`S2`) | `clog-metastore` provides `MetaStore` with two production backends—`ObjectStoreMetaStore` (one `object_store` conditional-PUT implementation covering S3, Azure, GCS, and local FS) and `clog-caspaxos` (Target `96`, SQLite-backed Fast CASPaxos for object-store-free clusters)—plus `InMemoryMetaStore` for tests. Separate cloud-specific `clog-azure`/`clog-s3`/`clog-gcs`/`clog-fs` crates are deleted. | [Storage](storage.md) |
| Hot ledgers (`S1`, `S5`, `ST11`) | `clog-wal` (`CLFL` direct-I/O WAL on Linux `io-uring` + portable `std::fs`) and multiplexed `LedgerStore` (`CLSC`/`CLSI`, using exact per-replica in-flight slot claims `LS-I7` rather than lock striping) back `clog-ledgers` (`LedgerQuorum` `N=3/Q=2` with zero-copy `Bytes` fan-out and inline fixed-capacity quorum tracking, `CLLM` v1 with scalar `archive_watermark: u64`, `CLLB`/`CLOE`, `ClusterController`). Each ledger carries an opaque 128-bit `LedgerId`. Roux's `clog-*` crates are algorithmically aligned with Clog and use idiomatic Rust + Protocol Buffers (`prost`/`protox`) for metadata/control records where cleaner, keeping custom binary framing only where alignment or key ordering requires it. | [Storage](storage.md) |
| Cold archive (`C1`, `ST2`, `ST3`) | `clog-archive` is a concrete SlateDB cold archive (no `ArchiveStore` trait or `clog-archive-logs`): one SlateDB instance per cluster (`wal_enabled = false`, `writer_epoch`-fenced elected drain writer, `DbReader` + `foyer` cache on all nodes). Order-preserving prefix-free keys `0x01 \|\| esc(RowKey) \|\| 0x00 0x00 \|\| Tag(20B)`; atomic `WriteBatch` commits rows + `\x00wm/{ledger_id}` + monotonic `\x00meta/commit_seq` (`await_durable = true`); `CLLM.archive_watermark` drives single-flight `DbReader` refresh (`HI-I2`). | [Storage](storage.md#3-slatedb-archive-c1-st2-st3) |
| Local warm index (`ST9`) | Pure-Rust WAL-less `lsm-tree` v3 (Fjall's core LSM crate) embedded directly inside `clog-journals` (`{root}/index/`), with no RocksDB, C++ FFI, or generic `clog-state-db` abstraction. Durability comes from `clog-wal` and live ledgers; derived flushes are driven by memtable budget (`64 MiB`), periodic `flush_interval = 30 s` watermark checkpoints, and clean shutdown; optional CRC-32C-checked `LedgerSegmentView` key-ordinal snapshots persist alongside watermarks (saved every `15 s` when advancing and at final watermark on shutdown, deleted on drop, falling back to `LG-I13` rewind on mismatch/corruption); `!is_archive_kind` (`RowKind::Message`) rows are skipped; startup replays unindexed WAL records and closed-ledger trees are dropped wholesale after archival. | [Storage](storage.md#2a-specialized-local-warm-journal-index-st9-wal-less-lsm-tree) |
| Pluggable key routing (`ST4`, `R36`) | `KeyRouter::route(&GrainId) -> RoutedKey { routing_key, journal_key }` with `RowKey = routing_key \|\| journal_key` opaque to `clog-journals`. Default `HashRouter` uses `xxhash32(canonical_grain_id, 0) \|\| canonical_grain_id`. Thread dispatch hashes the full `RowKey`. | [Storage](storage.md#4-pluggable-key-routing-contract-st4-r36), [Runtime](runtime.md) |
| Storage RPCs & ledger-replica leases (`ST5`, `ST7`, `ST8`, `ST10`) | `roux-storage` implements minimal `CLNR` (active nodes, `ProcessId` generation), L1 targets `96–100` (`roux.storage.v1`), soft `ClusterController` election (lowest live `Active` `NodeId` in Rapid `View` ∩ `CLNR`), L3 `ViewUpdate` → `ClusterController` (`clog-ledgers`) liveness bridge (`M39`), per-ledger quorum-intersecting replica leases (`ST8`: `D = 5 s`, idle `Heartbeat` `1.5 s`, `ρ = 10%`, guard band `δ = 1 s`, RAM `boot_lease_horizon` on restart, `max(lease_remaining_ms)` wait after seal before `LedgerMap` CAS), `PrepareRelease` → `RangeEvent::Releasing` cooperative drain (0 ms planned handoff), and `!Send` `JournalClient` bounded-channel bridge. | [Storage](storage.md) |
| Atomic journal messages & single-pass `DrainScan` folding (`ST12`, `LG-I15`, `LG-I16`, `JS-I11`, `JS-I12`) | General-purpose L2 atomic journal message system (usable for reminders, secondary index updates, CDC, audit, or atomic outbox pipelines): unversioned `RowKind::Message = 3` (`flags=0x03 \|\| channel_len \|\| channel_bytes \|\| body_len \|\| body_bytes`; zero `KeyRange`, zero `VersionBefore`/`RowToken`/`Ordinal`, zero `LedgerSegmentDictionary` or `lsm-tree` index writes, zero `CLLB` header or `CLLM` changes), atomic with journal writes via `HasMessagesFlag = 0x80` on `JournalEntryRecord`. Primary `MessageSession::on_batch_durable` runs strictly in slot order after quorum durability, outside admission lock, before warm-state apply and `Accepted`. Single-pass `DrainScan` `SegmentMessageFolds` (sharing `DrainMemoryBytes`) commits surviving `MessageProcessor` folds before advancing SlateDB's watermark (`0x00wm/{S}`), including message-only segments. `roux-storage` exposes generic `register_message_channel(handler, processor)`, roll-hint polling, `stop_message_handlers()`, and pre-`ArchiveGate` `StoreParameters` (`message-channels`, `max-messages`, `max-message-bytes`) validation. | [Storage](storage.md#3a-atomic-journal-messages-rowkindmessage--3-and-single-pass-drainscan-folding-st12-lg-i15-lg-i16-js-i11-js-i12) |
| Encryption at rest | Delegated to storage infrastructure (server-side encryption on object storage, encrypted volumes on local disks). | [Storage](storage.md) |

### L3 — Membership

| Area | Decision | Where |
| --- | --- | --- |
| Single membership crate & storage (`M36`–`M39`) | One `roux-membership` crate exposing the `Membership` trait backed by Rapid consensus. Persists `StoredView` (full newest view + producing entry) in a single `clog-metastore` register `{cluster:N}/membership` via conditional write on version `V − 1`. Membership extensions (`C8`, `Extension`, `submit`) and process manifests are omitted. | [Membership](membership.md) |
| Failure detection & health (`M11`–`M13`, `M27`–`M33`) | Rapid cut detection (`K = 10`, `H = 9`, `L = 3`, 1 s probes, 500 ms timeout, 3 consecutive failures) using built-in `Probe` RPC (no pluggable `EdgeFailureDetector` trait). `LocalHealth` monitors thread-stall signals only. | [Membership](membership.md) |
| Defunct retention & member lifecycle (`M9`, `M35`) | `Joining` → `Active` → `ShuttingDown` → `Left`, or any live status → `Dead`. Zero defunct members are retained in `View`; `ViewUpdate { view, from, changes }` carries `StatusChange` deltas so `Dead`/`Left` transitions are still delivered to subscribers. | [Membership](membership.md) |
| Membership wire schemas | `roux.membership.v1` `.proto` sum-type schemas for `Membership` (16) and `Join` (17). `Join` verifies `InstanceId` and `tls_key_sha256` against the connection. `Gateway` (18) is reserved for post-v1 client support. (Rapid peer leases `M29`/`C9` were withdrawn in favor of L2 ledger-replica leases `ST8`.) | [Membership](membership.md#wire-messages), [Wire catalog](wire-catalog.md) |

### L4 — Grain runtime and jobs

| Area | Decision | Where |
| --- | --- | --- |
| Owner-placed durable grains only (`R1`–`R7`) | All v1 grains are single-activation, owner-placed grains routed by `KeyRouter` → Clog `LedgerMapView` (no stateless grains, no `PreferCaller`/`Random` placement, no activation directory). Grain methods take `&self`; volatile state uses `Cell`/`RefCell`; durable state uses closure-scoped `read`/`update`; macro denies `clippy::await_holding_refcell_ref`. Explicit `NodeBuilder` registration (no `linkme`). | [Runtime](runtime.md) |
| Durability & staging (`R2`, `R3`, `R26`, `R30`) | Nil-externality: outgoing calls and responses wait for the durability of everything staged before them (per-activation durability watermark, one journal write in flight per grain). Staging flushes on dependent message release, `persist().await`, yield with no runnable segment, or 1 MiB cap. | [Runtime](runtime.md) |
| Call semantics & errors (`R4`, `R10`, `R11`) | At-most-once calls returning `Result<T, CallError<E>>` (`ran()` reports `No \| Yes \| Unknown`). Transparent resends only on `NotHere`, `Unavailable`, and local `NotSent` within deadline/hop limit. Cancellation is drop-based; deadlines propagate through `CallContext::current()`. | [Runtime](runtime.md) |
| Activation lifecycle & timers (`R6`, `R7`, `R14`, `R16`) | Synchronous `Grain::new(&GrainContext)` registers handles by explicit `StateId(u32)`, journal recovery folds into them (unknown `StateId`s in `StateSnapshot` fail recovery), then `on_activate` runs as the first turn. Deactivation (idle, handover, shutdown, failure) drops the grain synchronously (`Drop` only; no async `on_deactivate`). Panics or rejected appends terminate the activation. `ctx.register_timer` runs non-overlapping turns. | [Runtime](runtime.md) |
| Built-in durable state machines | `DurableValue`, `DurableMap`, `DurableList`, `DurableQueue`, `DurableSet`, `Inbox`, `Outbox`, and grain-local `DurableJobQueue` backed by the grain's journal. | [Runtime](runtime.md), [Overview](overview.md#journaling-and-durable-state) |
| Durable jobs & atomic journal reminders (`R32`, `R37`) | Partitioned backing scheduler grains (`JobShard`, `JobCursor`) in `roux-jobs` on ordinary Clog journals, paired with `"roux.reminder"` atomic `SetReminder` journal messages (first L4 consumer in `roux-jobs` registered into L2 `roux-storage` via `register_message_channel`, `ST12`): open-ledger `ReminderLedgerSession` timer heap (`is_ephemeral_reminder = true`), single-pass `DrainScan` `ReminderMessageProcessor` publishing 1 deterministic sealed `JobShard` per time bucket (`drain-{ledger:020}-{segStart:020}-{bucketUtcTicks:019}` via `CreateIfNotExists`, 0 writes when cleared in-segment), 1-RTT atomic `Inbox`/`Outbox` reminders via `GrainReminderCoordinator`, and grain-local `DurableJobQueue` with monotonic `execution_generation` cancel guard. | [Overview](overview.md#jobs), [Runtime](runtime.md#atomic-journal-reminders-and-grain-local-durable-jobs-r37) |

## Deferred (post-v1)

Captured here so the YAGNI scope boundaries remain explicit without cluttering active specs:

- **Storage:** `ObjectLedgerStorage` (diskless object-backed hot ledgers), SlateDB `2^k` sharding & RFC-0025 distributed compaction, volume-ordinal retirement (`RetireVolume`), standalone `clog-buffers` page-pool crate, and per-handle durability tracking (`R26`).
- **Networking & Serialization:** `ClientHello` / external client API / `Gateway` (18), kernel TLS (`kTLS`), `IORING_OP_SEND_ZC`, Unix domain sockets (`host_id`), `N29` head-first admission grants, `prost_types::Any`, and process manifests.
- **Membership:** Pluggable `EdgeFailureDetector` and retained defunct member history.
- **Runtime:** `CallControl` (64) wire cancellation (`Cancel`), `delete_state()`, `CompletionSource`, async `on_deactivate`, work stealing across threads, and off-owner/stateless activations.
- **Verification (milestone-gated):** `cargo-fuzz` decoder targets (added once wire/disk codecs land), mixed-version and persisted-fixture upgrade tests (added at the first format version bump), and `criterion` hot-path benchmarks (added once the end-to-end skeleton runs). (`cargo-mutants` in CI and TSan/`loom` are omitted unless custom lock-free atomics are introduced.)
